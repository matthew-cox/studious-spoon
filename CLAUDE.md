# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

URL shortener: JSON API + public redirects, an HTMX admin UI, an SQS click pipeline, Keycloak auth, and
OpenTelemetry. Runs locally on Docker/colima; designed to map onto AWS. The design spec is the source of
truth: `docs/superpowers/specs/2026-10-01-url-shortener-design.md` (key decisions D1–D14, permission
matrix §6.1, engineering constraints §15). Operations: `docs/operations.md`. Terraform for AWS is
designed but **not implemented** (`docs/adr/0001-terraform-aws-plan-ready.md`, plan + HANDOFF in
`docs/superpowers/plans/`).

## Commands

```bash
make sync                 # uv sync --all-packages --frozen
make check                # lint + typecheck + test (what CI runs, minus e2e/images)
make lint / make fmt      # ruff check + format --check / auto-fix
make typecheck            # mypy --strict over every package's src/
make test                 # unit + integration, coverage ≥80% overall, ≥90% branch on PURE_MODULES
make up / make down       # full compose stack (down deletes volumes)
make e2e                  # e2e tests against the running stack (needs make up)
make token USER=eddie     # access token for a seeded user
```

Single test / subset — use `scripts/test.sh`, which sources `scripts/docker-env.sh` so testcontainers
finds the Docker runtime (colima needs a socket override):

```bash
scripts/test.sh api/tests/unit/test_policy.py -k blocked
scripts/test.sh admin -k csrf
scripts/test.sh -m "not integration"     # skip tests that need Docker
```

Plain `uv run pytest` works only after `. scripts/docker-env.sh`. Default pytest addopts exclude `-m e2e`.
Integration tests are marked via module-level `pytestmark = pytest.mark.integration`.

## Layout (uv workspace)

- `api/` (`shortener_api`, port 8000) — `/api/v1/...` + `GET /{code}` redirects. Owns Alembic migrations (`api/alembic`).
- `processor/` (`shortener_processor`, 8002 health only) — consumes `click-events`, writes `analytics.*` rollups.
- `admin/` (`shortener_admin`, 8001) — FastAPI + Jinja2 + HTMX; vendored static assets.
- `libs/shortener-events` — `link.clicked` event model/codec; committed JSON schema regenerated by `scripts/gen-event-schema`.
- `libs/shortener-observability` — shared OTel setup, JSON logging, trace propagation, DB instrumentation.
- `libs/shortener-testing` — shared testcontainers fixtures (Postgres with migrations applied, ElasticMQ). Image tags must match `docker-compose.yml`.
- `tools/keycloak-tools` — idempotent user seeding from `infra/keycloak/users.yaml`, token helper.
- `tests/` — repo-level tests (dashboard, `.env.example`, launchpad) and `tests/e2e`.
- `infra/` — compose config for Postgres bootstrap, Keycloak realm, ElasticMQ queues, Grafana dashboards.

Adding a workspace member: add it to `[tool.uv.workspace]`, the `COPY .../pyproject.toml` list in
**every** Dockerfile (uv must resolve the whole workspace), `MYPY_TARGETS` in the Makefile, ruff `src`,
and coverage `source`.

## Architecture (the parts that span files)

- **Authorization lives only in the API.** `shortener_api/policy.py` `decide(principal, action, link)`
  returns ALLOW/403/404/409; routes call it, nothing else decides. Non-owners get 404, not 403. Owner
  `is_active` and admin `blocked_*` are separate fields so unblocking restores prior state (D6).
- **Admin UI is a token relay.** It holds Keycloak tokens in server-side sessions (`admin.sessions` in
  Postgres; browser gets only an opaque `sid`) and calls the API with the user's own token. It never
  makes authorization decisions itself.
- **Click pipeline.** Redirect → `BufferedClickPublisher.publish()` only enqueues in memory (never blocks
  the redirect; drops + counts metric when full) → background flusher `SendMessageBatch` to SQS
  (ElasticMQ locally) → processor batches up to 100 msgs/1 s → pure `aggregate()` → one transaction of
  upserts → delete messages only after commit. At-least-once; slight overcount accepted (D13). Invalid
  messages are left to hit the DLQ after 5 receives. Batch spans *link* to producer spans.
- **Separate DB users per service** (`api_user`, `processor_user`, `admin_user`, `migrator`) with schema
  grants (spec §3.4); the processor can't lock `public.links`. Migrations run only via the `migrate`
  one-off job (`make migrate`), never at app startup.
- **Composition roots.** Each service builds real dependencies in one place (`api/main.py:build_deps`,
  `processor/main.py:build_runtime`) and injects them; tests swap in fakes (`InMemoryClickPublisher`,
  fake JWKS provider with test-minted RSA tokens, `Clock`, seeded random for codes).

## Conventions (from spec §15)

- Pure modules (`policy`, `codes`, `urls`, `stats`, `aggregate`, `referrers`, `security`, events codec)
  must not import FastAPI, SQLAlchemy, boto, or httpx. They're listed in `PURE_MODULES` in the Makefile
  with a 90% branch-coverage gate — add new pure modules there.
- TDD: start each behavior/bug fix with a failing test. Prefer hand-written fakes; mock only outside HTTP
  boundaries with `respx`. No `sleep` in unit/integration tests; no SQLite stand-ins (real Postgres via
  testcontainers).
- Config only from env vars via one `pydantic-settings` class per service; invalid config fails at
  startup; no `if env == "prod"` branches. Every variable must be documented in `.env.example`
  (`tests/test_env_example.py` checks it against `${VAR}` references in `docker-compose.yml`).
- Executable Python scripts go in `scripts/` with a uv shebang (`#!/usr/bin/env -S uv run --quiet --script`)
  and PEP 723 header. Library modules and container entrypoints use `python -m`.
- Grafana dashboard is code: edit `scripts/gen-dashboard`, rerun it; tests fail if
  `infra/otel/dashboards/shortener-overview.json` is stale.
- Pin all images and tool versions (never `:latest`); ruff line length 100; mypy strict.

## Local gotchas

- Keycloak port conflict: set `KEYCLOAK_HOST_PORT` and `KEYCLOAK_URL` in `.env`, then `make down && make up`.
- Realm/Postgres role/Keycloak admin changes only apply on fresh volumes: `make down && make up`.
- Seeded users (password `password`): alice=admin, eddie/erin=editor, victor=viewer, nora=no role.
